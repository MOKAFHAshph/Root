# تقرير المراجعة الفنية

## السبب الجذري لتعطل `/start`

المشروع يستخدم مسجل توافق لمشاركة الرموز بين وحدات تم تحميلها بالتتابع. كانت دالة خاصة باسم `_font_candidates` موجودة في وحدة CAPTCHA ووحدة PDF، لكن كل واحدة تعيد نوع بيانات مختلفًا.

بعد اكتمال التحميل، كانت `runtime.sync_all()` تستبدل حتى الرموز الخاصة في جميع الوحدات. لذلك أصبحت دالة CAPTCHA تستدعي دالة PDF وتحاول تنفيذ `is_file()` على قائمة، فظهر استثناء قبل إرسال الصورة، ثم التقطه معالج الأخطاء العام وأرسل رسالة لا تناسب مستخدمًا جديدًا.

تم الإصلاح بطبقتين:

1. منع المزامنة النهائية من استبدال أي رمز خاص موجود محليًا داخل الوحدة.
2. منح مساعدات خطوط CAPTCHA وPDF أسماء فريدة.

أضيف اختبار يشغل `/start` الحقيقي على قاعدة SQLite مؤقتة ويتأكد من الوصول إلى حالة CAPTCHA، كما يفحص جميع مراجع الرموز العالمية بعد التحميل.

## مراجعة الإحالات

- حفظ الإحالة يتم قبل الاشتراك وCAPTCHA.
- المستخدم لا يستطيع إحالة نفسه.
- يجب أن يكون المُحيل معروفًا للنظام.
- `referred_telegram_id` فريد لمنع تغيير المُحيل لاحقًا.
- تكرار `/start` آمن ولا ينشئ إحالة ثانية.
- فشل الإحالة يسجل الخطأ لكنه لا يوقف التسجيل.
- المكافأة تُضاف مع Ledger وتغيير الحالة في معاملة واحدة.

## مراجعة الإيداع

- لا توجد حالة `await_wallet_deposit_yer` في المعالج النهائي.
- المبلغ يبدأ بصفر ويظل كذلك حتى نتيجة جيب.
- لا يحجز رقم العملية قبل نجاح الاستعلام، حتى يستطيع المستخدم تصحيح رقم غير موجود.
- بعد العثور على العملية يحجز المرجع في `BEGIN IMMEDIATE` لمنع السباق.
- القيمة المستخرجة هي التي تُخزن وتُضاف.
- لا يسمح بإضافة قيمة غير موجبة.
- عدم ظهور الهاتف أو اختلافه لا يؤدي إلى رفض أعمى أو إضافة تلقائية؛ ينتقل إلى مراجعة الإدارة.

## مراجعة السحب

- الحجز والإرجاع والإكمال معاملات ذرية.
- الإكمال والإرجاع قابلان لإعادة الاستدعاء بأمان حسب حالة العملية.
- لا يسمح `wallet_mark_submitted` بإعادة فتح عملية مكتملة أو أعيد رصيدها.
- تم تصحيح خطأ اسم متغير في سجل إكمال السحب، واكتشفه اختبار مسار الإكمال الفعلي.

## قاعدة البيانات

- WAL و`busy_timeout=30000` لتقليل `database is locked`.
- `foreign_keys=ON` لكل اتصال.
- فهارس جزئية للهواتف غير الفارغة.
- فحص Foreign Keys بعد الاستعادة.

## السجلات

- File وConsole handlers مُداران مركزيًا.
- إعادة تطبيق الإعدادات لا تضيف Handlers مكررة.
- التصفير يمسك Lock الخاص بالـ Handler ويقص Stream نفسه، وهي طريقة آمنة على Windows.
- حجب الأسرار يتم قبل الإخراج وبعد Formatting لتغطية Stack Trace، ويطبق أيضًا قبل حفظ الحدث التقني في SQLite أو إرساله إلى Telegram.
- سجل استجابات جيب الخام منفصل وحساس، يُحفظ افتراضيًا داخل `exports/` مع صلاحيات مقيدة وتدوير تلقائي.

## الاستعادة المحلية

- الاستعادة القديمة من مجلد `backups` مقيدة بملفات JSON الموجودة داخل المجلد نفسه لمنع الخروج إلى مسارات أخرى.
- ينشئ النظام نسخة أمان من الحالة الحالية قبل تنفيذ الاستعادة المحلية أو الاستعادة من القناة أو الملف المرفوع.

## حدود التحقق

تمت اختبارات غير متصلة على الكود وقاعدة بيانات مؤقتة ومحاكيات لاستجابات Telegram وجيب وBinance. لم تُجرَ تحويلات مالية حقيقية أو اتصالات حية بجيب/Binance/Telegram في بيئة البناء. يلزم اختبار Staging بمبالغ صغيرة قبل الإنتاج.
