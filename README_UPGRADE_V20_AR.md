# التحديث 20 — دليل التركيب والاستخدام

هذه حزمة المشروع كاملة بالكود المحدث. لا تحتوي على ملف `.env` أو قاعدة العملاء أو عبارة المحفظة أو السجلات. تستخدم محفظة TON الحالية نفسها، ولا تحتاج إنشاء محفظة جديدة. هذا الدليل هو المرجع الحالي؛ أدلة الإصدارات الأقدم تاريخية.

## ما أصبح متاحاً

- **محفظة TON للإدارة داخل التطبيق المصغر**: أرصدة USDT وTON، السيولة الحرة بعد الطلبات المحجوزة، تقدير بالدولار مع حالة السعر، عنوان الاستقبال وQR، إرسال يدوي للعملتين مع مراجعة وتأكيد ثانٍ، وسجل عمليات وإثباتات الشبكة.
- **الرسوم الحقيقية**: يعرض السجل تكلفة المحفظة النهائية بـTON، والمبلغ المرفق للتنفيذ والمسترد عندما تتوفر بياناتهما. المبلغ المرفق ليس العمولة. قيمة الدولار تقريب بسعر العرض الحالي، وليست تكلفة تاريخية مثبتة. يدعم جمع رسوم العمليات المسجلة لفترة بتاريخ UTC.
- **تأكيد سحب USDT على TON**: مطابقة الرسالة الموقعة مع تتبع نهائي وإثبات استلام USDT الصحيح، ثم إكمال الحجز والإشعار مرة واحدة. تقبل حالة `finalized` الفعلية من المزود. فشل إشعار جانبي لا يلغي إثبات وصول USDT إلى عقد المستلم.
- **طابور واحد للمحفظة** بين سحوبات العملاء والإرسال والمبادلة اليدوية، مع قفل وملكية للعملية ومنع تكرار التأكيد والحجز والإكمال. العملية الموقعة مجهولة النتيجة تُراجع على الشبكة؛ لا تنشأ محاولة دفع جديدة تلقائياً. قد توقف عملية غامضة الطابور حتى تُحسم لحماية الأموال.
- **تشخيص جيب**: فحص إعدادات العميل، DNS والاتصال وTLS وتسجيل الدخول والاستعلام، أسباب مفهومة وسجل انقطاع وتراجع تدريجي للمحاولات. أدوات حالة الخدمات للقراءة فقط. إعادة فحص الإيداعات المؤهلة تستخدم التحقق المالي نفسه ولا تضيفها بمجرد عودة الاتصال.
- **تخصيص البوت** من Mini App: البحث بين الرسائل والأزرار، تعديل النص والرموز والنمط مع معاينة واستعادة الافتراضي، واسم الخدمة والترحيب وترتيب القائمة. الوظائف ومعرّفات الأزرار ثابتة. التخصيص لا يعيد تسمية تنقل التطبيق المصغر.
- **آخر عنوان مكتمل لنفس العميل ونفس الشبكة** في البوت والتطبيق، مع إمكانية كتابة عنوان جديد ومراجعة مستقلة للتعليق والعنوان والمبلغ.
- **مبادلة إدارية اختيارية عبر STON.fi** بين USDT وTON، بعرض قابل لبناء المعاملة، حد استلام وانزلاق وصلاحية قصيرة. يوقّع Python داخل السيرفر؛ باني الرسائل لا يتلقى عبارة الاسترداد.

## الحدود التي يجب معرفتها

1. **إيداع جيب دون رقم العملية غير مفعّل**: المشروع لا يوفر واجهة موثقة لكشف جميع التحويلات. بقي الاستعلام برقم العملية، ولا توجد واجهة مختلقة أو مطابقة بالمبلغ فقط. يوجد موصل قابل للربط لاحقاً بعد التحقق من مصدر الكشف وحدود التوقيت وهوية المرسل؛ التفاصيل في دليل 19.
2. بيع TON الأصلية للعميل يبقى مخفياً ومتوقفاً. سحب العميل على شبكة TON يرسل **USDT**، ويتحمل البوت رسوم الإرسال. BEP20 يبقى عبر Binance وبإعداداته الحالية؛ التحديث لا يثبت أو ينفي أي خبر عن Binance.
3. واجهة الإدارة تدير المحفظة التشغيلية الحالية. ليست بديلاً مطابقاً لكل وظائف Tonkeeper؛ لا إدارة NFT أو عملات عشوائية أو عرض عبارة الاسترداد في الويب. المزامنة تجلب حركات حديثة، وليست فهرسة لكل تاريخ السلسلة. إجمالي الرسوم يخص الإيصالات المسجلة في النظام، وليس جميع استخدامات العنوان خارج البوت.
4. رمز Custom Emoji يعتمد على أهلية البوت وقيود Telegram: Premium للمالك في السياقات المدعومة أو اسم إضافي مؤهل من Fragment. الرمز العادي بديل عند رفض Telegram الرمز/النمط. حفظ معرّف الرمز وحده لا يمنح الأهلية.
5. المبادلة اليدوية مغلقة افتراضياً. لم تُنفذ أثناء التطوير مبادلة أو دفعة حقيقية. اختلاف استجابة المزود أو غياب الدليل النهائي يؤدي إلى مراجعة، وليس إلى افتراض النجاح أو إعادة إرسال أو رد رصيد سبق إرساله.

## التركيب على سيرفرك الحالي

ارفع `bot-update-v20.zip` إلى `/root/`. فكّه في مجلد مستقل؛ لا تفكّه مباشرة فوق المشروع:

```bash
mkdir -p /root/update20
unzip /root/bot-update-v20.zip -d /root/update20
cd /root/update20/o
sha256sum -c SHA256SUMS_V20.txt
/root/o/.venv/bin/python tools/install_update20.py --target /root/o
```

الأمر الأخير فحص فقط. إذا نجح، أوقف الخدمة لتثبيت الملفات دون تعارض مع عملية مالية قيد التنفيذ:

```bash
systemctl stop jaib.service
/root/o/.venv/bin/python /root/update20/o/tools/install_update20.py --target /root/o --apply
/root/o/.venv/bin/python -m pip install -r /root/o/requirements.txt
systemctl start jaib.service
systemctl status jaib.service --no-pager --full
```

إذا فشل التثبيت أو تثبيت الاعتماديات، عالج السبب قبل تشغيل الخدمة. المثبّت يطبع مكان نسخة احتياطية خاصة بجوار المشروع تحت `.usdt-update-backups`، ويحافظ على `.env` وقاعدة البيانات وملف المحفظة. ينقل حقول تعريف عميل جيب القديمة إلى `.env` عند وجودها في المصدر القديم، دون طباعتها. لا يغير DNS أو Cloudflare أو Nginx، ولا يشغّل أو يوقف الخدمات بنفسه. ترحيل الجداول يحدث عند تشغيل التطبيق. لا تسترجع قاعدة قديمة بعد حدوث دفعات جديدة دون مطابقة مالية.

لا تنسخ `.env.example` فوق إعداداتك. أبقِ `TON_HOT_ADDRESS` و`TON_MNEMONIC_FILE` و`TONCENTER_API_KEY` الحاليين. لا تشغّل أدوات إنشاء المحفظة أو تهيئتها مجدداً للمحفظة المهيأة. أبقِ نسخة cloudflared الخاصة بالسيرفر وحدها؛ تشغيل نفس النفق على حاسوب Windows الذي لا يستضيف التطبيق يعيد مشكلة 502 السابقة.

## أين تجد الأدوات؟

افتح التطبيق المصغر بحساب الأدمن ثم الإدارة:

- **محفظة TON**: الأرصدة، استقبال، إرسال يدوي، مبادلة، السجل والرسوم، الإعدادات. تتطلب صلاحية `wallet_settings`.
- **اتصال جيب**: فحص سريع أو شامل ونتائج المراحل وسجل الحالة. يتطلب `wallet_settings`. الفحص لا يغير إعدادات السيرفر.
- **واجهة البوت**: اختر المجموعة والعنصر، عدّل النص مع إبقاء متغيرات العملية، ثم حفظ ونشر. تتطلب `settings_sales`.

إغلاق سحب TON يمنع طلبات العملاء الجديدة، وتستمر مطابقة العمليات الموقعة. الإرسال الإداري صلاحية مستقلة. حدود السيولة العليا تنبيه وليست حائطاً يمنع الإيداعات الخارجية؛ غذِّ المحفظة بقدر الحاجة.

## معالجة السحب السابق المعلّق

بعد التحديث افتح محفظة TON ← السجل والرسوم ← العملية ← **مطابقة الشبكة فقط**. هذه الخطوة لا تعيد إرسال الأموال. يمكن كذلك إجراء فحص قراءة فقط من السيرفر للطلب السابق ذي المعرّف 58:

```bash
/root/o/.venv/bin/python /root/o/tools/ton_audit.py --withdrawal-id 58
```

إذا ثبت الاستلام النهائي، يسوي المسار المالي الحجز ويحدّث حالة الطلب ويُنشئ إشعار النجاح مرة واحدة. إذا بقيت الحالة غامضة، لا تحذف صف `ton_outbox` ولا تعد الرصيد أو تكرر السحب يدوياً دون إثبات.

## تشغيل المبادلة الإدارية عند الحاجة

يتطلب Node.js 22 أو أحدث وnpm. بعد توفرهما:

```bash
cd /root/o/ton-dex
npm ci --omit=dev
node test-build.mjs
```

أضف `TON_ADMIN_SWAP_ENABLED=true` إلى `.env` ثم أعد تشغيل `jaib.service`. لا تحتاج المبادلة إلى ملف مفاتيح جديد. ابدأ بعرض سعر ومراجعة مبلغ صغير؛ العرض لا يرسل أموالاً، والإرسال يحتاج تأكيد الأدمن الثاني. يمكن تعطيلها بإعادة المتغير إلى `false`.

اختير STON.fi لتوفر المحاكاة وSDK الذي يبني رسالة تتطابق مع العرض. DeDust يستخدم خزائن ومجمعات وله مسار بناء مختلف. لا يمكن الجزم بالأرخص دون مقارنة عروض التنفيذ والسيولة والغاز وقت الطلب. لم نضف موزع مسارات بين المنصتين يزيد مساحة الخطأ.

## تحقق قصير بعد التركيب

افتح الصفحة والأدوات الثلاث، راجع رصيدي TON/USDT، وطابق السحب السابق أولاً. جرّب تخصيص زر غير مالي ثم استعادته. بعد حسم أي طلب غامض، اختبر سحب USDT صغيراً مرة واحدة: تأكد من وصول المبلغ كاملاً، اكتمال الطلب، ظهور رسم TON الفعلي، وأن التأكيد المكرر لا ينشئ دفعة ثانية. تفاصيل التحقق المحلي في `TEST_RESULTS_V20.md`.
